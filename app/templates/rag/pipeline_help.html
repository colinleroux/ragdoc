How to Use RagDoc Pipeline

RagDoc is built as a small RAG lab. The usual flow is: set up the pipeline, ingest a corpus, ask questions, review answers, and then compare results across models, ask settings, and ingestion presets.

Recommended Workflow

  1. 1. In Setup, choose generation model, embedding model, collection, and optional judge settings.
  2. 2. In Inputs, confirm corpus files, choose an ingestion preset, then ingest.
  3. 3. In Query, load saved ask settings or write an ad hoc question and ask.
  4. 4. In Answers, review the answer, rate it, and open comparisons.
  5. 5. In Judge, run structured evaluations when you want stricter comparison.

Setup Tab

  • Choose the docs path, vector collection, generation model, and embedding model.
  • Use a fresh collection when you change embedding models.
  • Run Check Settings before downloading large models.
  • If judge is enabled, choose a separate judge model for evaluation.

Inputs Tab

  • Review the files in the current docs folder.
  • Choose an ingestion preset that matches the embedding model and corpus style.
  • Use chunk preview to inspect what ingestion actually produced.
  • Reset clears ingested sources, chunks, embeddings, and the active Qdrant collection, but not the source files themselves.

Query Tab

  • Load saved ask settings when you want apples-with-apples comparisons.
  • Use top K, source count, strictness, minimum score, and reasoning mode to shape answer behavior.
  • If you are comparing models, hold the ask settings constant.

Answers Tab

  • Every successful ask is captured with answer text, sources, settings, and metadata.
  • Rate runs manually as satisfactory or not satisfactory.
  • Click a question to open question-based comparison across models, ask settings, or ingestion presets.
  • Use Delete All when you want a clean run set before a fresh experiment pass.

Judge Tab

  • The judge checks the answer only against retrieved chunks, not outside knowledge.
  • Keep judge disabled while collecting runs if you want to move quickly, then re-enable it later for batch evaluation.
  • Judge failures are useful diagnostics: retrieval, hallucination, evasiveness, incompleteness, or citation weakness.

Experiment Tips

  • Change one variable at a time when you can: model, ask settings, or ingestion preset.
  • Use separate collections for different embedding models.
  • Keep a small fixed question set for baseline comparisons.
  • If embeddings fail with a tighter model, create a smaller chunking preset and use page-based PDF mode.
